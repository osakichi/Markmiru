# Markmiru スタイル設定設計（閲覧モード）

最終更新: 2026-07-22

閲覧モードの表示スタイルを細かく調整し、かつ**クロスプラットフォームで同一表示**を実現するための設計。全体方針は [`アーキテクチャ・画面設計.md`](アーキテクチャ・画面設計.md) を参照。

## 0. 確定方針

| 項目 | 決定 |
|------|------|
| 表現方式 | **構造化「スタイル」(JSON) ＋ CSS 変数**で適用 |
| フォント | **同梱する**（一致を保証）＋**システムフォントも選択可**（選んだ場合は OS 間で差異が出る旨を UI で明示〔注意書き UI は**未実装**〕） |
| 同梱フォント構成 | **A. Noto 統一**（Noto Sans JP / Noto Serif JP / Noto Sans Mono）。すべて SIL OFL・無償。約 5MB（weight 400/700、woff2 サブセット）。等幅は CJK 版（Noto Sans Mono CJK JP）の woff2 が入手できないため、ラテン専用の Noto Sans Mono ＋ 日本語は Noto Sans JP フォールバックで暫定対応（方式A）。日本語等幅合成フォントの同梱（方式B）は将来拡張 |
| 編集方法 | **GUI 設定パネル ＋ カスタム CSS**（上級者向けエスケープハッチ）の2層 |
| 適用範囲 | **グローバル**（アクティブな1スタイルを全ドキュメントへ適用） |
| Light / Dark | 独立機能ではなく、スタイル内の**配色のプリセット**として扱う |
| 標準プリセット | **ライト / ダーク / GitHub 風 / セピア**（複製・編集できる雛形。後から追加可） |
| コード/mermaid テーマ | **スタイルの colorScheme(light/dark) に連動**（個別固定指定は未実装・将来拡張） |
| 印刷 / PDF 出力 | **印刷向けに変換**（紙=白背景・濃色文字。組版はスタイル継承）（§5.2） |

## 1. 基本方針：スタイル ＋ CSS 変数

スタイルを1つの構造化データ（JSON＝**スタイル**）として保持し、適用時に **CSS 変数（カスタムプロパティ）**へ展開する。プレビュー用スタイルシートはこの変数群のみを参照する。

```text
スタイル(JSON)
   → CSS 変数群 (--md-*) を生成・ルートへ適用
   → プレビュー用スタイルシートが var(--md-*) を参照
   → 描画
```

- 同じスタイル → 同じ変数 → 同じ生成 CSS となるため、**環境を問わず同一の見た目**を再現できる。
- スタイルは**保存・複製**でき、ファイルベースの**エクスポート/インポート**（封筒形式 JSON）で別マシン・別 OS へ持ち運べる（§6）。

## 2. 調整可能なパラメータ（カタログ）

各項目は CSS 変数に対応し、GUI 設定パネル（モーダル）から調整できる（実装: スタイル定義は `style/style.go` の `Style`、CSS 変数生成は `style.CSS`、設定 UI は `web/templates/fragments.html` の `settings-modal` / `numfield` / `colorfield`、更新は `POST /settings/field/{key}` 等）。

| カテゴリ | 項目 | 対応 CSS 変数 |
|----------|------|---------------|
| **全体（本文）** | フォント / 基準サイズ(px) / 行間 / 文字色 / 背景色 / 本文最大幅(px・全幅トグル) | `--md-font`, `--md-font-size`, `--md-line-height`, `--md-color`, `--md-bg`, `--md-max-width` |
| **見出し h1〜h6（レベル毎）** | フォント / サイズ(px) / 太さ(100〜900) / 色 / 上マージン(em) / 下マージン(em) / 下線(有無) | `--md-h{n}-font`, `--md-h{n}-size`, `--md-h{n}-weight`, `--md-h{n}-color`, `--md-h{n}-mt`, `--md-h{n}-mb`, `--md-h{n}-border` |
| **インラインコード** | 背景（フォントはコードブロックと共通。サイズは本文サイズの 0.9 倍固定で `--md-code-size` の対象外） | `--md-code-font`, `--md-code-bg` |
| **コードブロック** | 等幅フォント / 文字サイズ(px) / 背景 | `--md-code-font`, `--md-code-size`, `--md-pre-bg` |
| **引用(blockquote)** | 文字色 / 背景 / 左ボーダー色 / 左ボーダー太さ(px) / イタリック | `--md-quote-color`, `--md-quote-bg`, `--md-quote-border`, `--md-quote-border-width`, `--md-quote-style` |
| **箇条書き（リスト）** | インデント幅(px) / マーカー色 / マーカーサイズ(em) / マーカー位置(outside/inside) | `--md-list-indent`, `--md-marker-color`, `--md-marker-size`, `--md-list-position` |
| **リンク** | 色 / 下線(always/hover/none) | `--md-link-color`, `--md-link-deco`, `--md-link-deco-hover` |
| **表(テーブル)** | 境界線の色 / ヘッダ背景 / 奇数行背景 / 偶数行背景 | `--md-border`, `--md-th-bg`, `--md-row-odd-bg`, `--md-row-even-bg` |
| **水平線(hr)** | 色 / 太さ(px) | `--md-hr-color`, `--md-hr-thickness` |

- コード（インライン・ブロック）の**等幅フォントはスタイル共通**（`codeFontFamily`）。文字サイズ（`codeFontSize`）は**コードブロックと編集オーバーレイに適用**され、インラインコードは本文サイズの 0.9 倍（`0.9em` 固定）に追従する。背景はインライン（`--md-code-bg`）とブロック（`--md-pre-bg`）で個別指定する。
- 表のストライプは**奇数行・偶数行の背景色**で表現する（ON/OFF トグルではない）。
- **控えめな文字色 `--md-muted`**（脚注・遮断した外部画像の表示）は**スタイル項目ではなく派生値**で、`markdown.css` の `.markdown-body` が本文の文字色を背景色へ寄せて導く（`color-mix(in srgb, var(--md-color) 70%, var(--md-bg))`）。そのためライト／ダーク／セピア等やユーザー編集の配色に自動で追従する（印刷時も、ダーク系では §5.2 の差し替え後の配色から導かれる）。2026-09-25 まではどこでも定義されておらず、脚注は本文と同じ色だった。color-mix 非対応の WebView（macOS の Safari 16.2 未満相当）では使用側で無効になり、従来どおり本文の文字色になる。
- コードのシンタックステーマ（chroma）と mermaid テーマは CSS 変数ではなく、スタイルの `colorScheme`（light/dark）に連動してレンダリング処理側で切替える（§5.1）。
- 上記に加え、**カスタム CSS**（`customCSS`）で `.markdown-body` 配下を直接上書きできる（§4）。

## 3. クロスプラットフォームで同一表示にする仕組み

### 3.1 ズレの原因

1. **フォント**: OS により搭載フォントが異なり、字形・字幅が変わる。
2. **WebView エンジン差**: 本アプリは OS 標準 WebView を使うため、**Windows=Blink(WebView2) / macOS・Linux=WebKit**。UA 既定スタイルや既定マージンに微差が出る。

### 3.2 対策

| 対策 | 内容 | 効果 |
|------|------|------|
| **フォント同梱** | 既定フォントをアプリに埋め込み、`@font-face` で固定 | OS 非依存で字形・字幅が一致 |
| **CSS リセット/ノーマライズ** | UA 既定を打ち消し、全プロパティを明示指定（既定値に依存しない） | エンジン差による既定マージン等を排除 |
| **単位・ボックスモデル統一** | `box-sizing` 統一、`px`/`rem` を一貫、基準サイズ固定 | レイアウト・サイズが一致 |
| **構造化スタイル** | 同一スタイル→同一 CSS 変数→同一生成 CSS | どの OS でも同一の見た目を再現 |

### 3.3 同梱フォント（確定：A. Noto 統一）

本アプリは日本語 UI／日本語文書が主のため、**日本語対応（CJK）フォントを同梱**する。Noto ファミリで統一する。

| 用途 | フォント | ライセンス |
|------|----------|-----------|
| 本文ゴシック | Noto Sans JP | SIL OFL 1.1 |
| 本文明朝 | Noto Serif JP | SIL OFL 1.1 |
| 等幅（コード） | Noto Sans Mono（ラテン専用）＋ 日本語は Noto Sans JP フォールバック | SIL OFL 1.1 |

- すべて **SIL OFL 1.1・無償**。アプリへの埋め込み・再配布・商用同梱が可能（条件: フォント単体での有償販売不可／OFL ライセンス文の同梱／予約フォント名を改変版に使わない）。
- 同梱は **Regular / Bold に絞る**（Thin〜Black 全部入れると数倍に膨張するため）。
- **等幅の日本語は等幅にならない（実装上の制約）**: CJK 等幅の Noto Sans Mono CJK JP は実在するが woff2 として入手できないため同梱せず、ラテン専用の Noto Sans Mono を同梱し、日本語グリフは Noto Sans JP（プロポーショナル）へフォールバックさせている（方式A）。日本語まで等幅にするには日本語等幅合成フォントの同梱（方式B）が必要で、これは将来拡張。
- 概算サイズ: woff2（weight 400/700・サブセット）で **約 5MB**。Wails 本体が軽量なため許容範囲。
- **実装**: woff2 を `web/assets/fonts/` に直 vendor し、`web/assets/fonts.css` の `@font-face`（サブセット別ファイル定義。`unicode-range` 指定は無し）で定義、`//go:embed` で同梱する（@fontsource のサブセットを vendoring 済み。再生成は `scripts/vendor-fonts.sh`）。ライセンス文（OFL）は `LICENSE.md` に統合して同梱する。

### 3.4 残る差と注意

レイアウト・サイズ・字形は実質同一にできるが、**アンチエイリアス／ヒンティング等の OS レベルの描画差**はごく僅かに残る（文書用途ではほぼ知覚不可）。完全なピクセル一致は保証対象外とする。

### 3.5 システムフォント選択時

ユーザーがシステムフォントを選んだ場合は一致保証の対象外となるため、**UI 上で「OS 間で表示が異なる可能性」を明示**する〔注意書き UI は**未実装・将来対応**——現状は選択肢の提供のみ〕。

## 4. 編集方法（GUI ＋ カスタム CSS）

- **GUI 設定パネル**（モーダルダイアログ）: カタログの各パラメータを、**スライダー＋数値入力**の対・**カラーピッカー＋HEX テキスト**の対（対の値は glue が相互同期）・フォント選択で調整。変更は **htmx で `#styleblock`（CSS 変数）だけを差し替える**ライブプレビューで即時反映（本文再描画なし）。色は `#rrggbb` 専用で、`transparent`/`rgba` 等の非 hex 値の直接入力は非対応（既定値は CSS 変数としてそのまま反映され表示は維持）。
- **カスタム CSS（上級者向け）**: GUI で届かない細部を直接上書き。スタイル内 `customCSS` として保持し、生成 CSS の後段に適用する。

## 5. 適用範囲（グローバル）

- アクティブなスタイルは1つ。**全タブ・全ドキュメントに一律適用**。
- スタイルの切替で、開いている全ドキュメントの表示が即座に変わる。
- （将来拡張）ドキュメント毎の個別指定は必要に応じて検討。

### 5.1 コード/mermaid テーマの連動（確定・実装済み）

閲覧モードの**コードブロックの構文色（chroma）と mermaid 図の配色**は、スタイルの `colorScheme`（light/dark）に連動させる（実装: コードは `render.HighlightCSS`（chroma の github / github-dark を `<style id="markmiru-code-theme">` に注入）、mermaid は glue.js が本文の `data-scheme` からテーマを選ぶ）。

| colorScheme | コード(chroma) | mermaid |
|:---:|------------------------------|---------|
| light（ライト / GitHub 風 / セピア） | `github` | `default` |
| dark（ダーク） | `github-dark` | `dark` |

- **連動** = コード/mermaid を `colorScheme` に対応する明/暗テーマへ自動追従。現状はこの自動連動のみ。
- **個別固定指定**（本文はライトだがコードのみ暗テーマ等）は**未実装・将来拡張**。
- mermaid は `securityLevel: 'strict'` で初期化する（未知ソースでも安全側）。
- **注記**: ここでの対象は**閲覧モード（レンダリング表示）**のコード/図。**編集モード（透明 textarea ＋ chroma オーバーレイ）の外観は別管理**（§9 参照。`colorScheme` の Light/Dark のみ連動）。

### 5.2 印刷／PDF 出力時のスタイル（確定）

印刷・PDF 出力時のスタイルは、画面の配色（特に Dark）をそのまま紙に出すと不適切なため、**印刷向けに変換**する。

| 項目 | 背景 | 文字色 | 組版（フォント/サイズ/余白） |
|--------|------|--------|------------------------------|
| **印刷向けに変換** | 紙の色（白） | 濃色（黒／印刷用フォントカラー） | アクティブなスタイルを**継承** |

- **挙動**: 組版（フォント・サイズ・行間・余白・レイアウト）は**アクティブなスタイルから引き継ぎ、配色だけを印刷用（白背景＋濃色文字）に差し替える**。Dark 表示中でも印刷物は読みやすい紙向けになり、白文字が白背景に乗って消える事故も防ぐ。印刷は `POST /active/print`（アクティブを閲覧モードにし、本文を `scheme=light` で描画、`HX-Trigger-After-Settle: do-print` で glue が Go の `Print` を呼ぶ。macOS は自前の `NSPrintOperation` によるネイティブ印刷パネル（縦向きデフォルト・向き/用紙サイズ/拡大縮小をパネルで変更可・用紙余白は Windows/Linux の既定と同等の約 1cm）、Windows/Linux は Wails `WindowPrint` 経由の `window.print()`）。
- 実装は**印刷用 CSS（`@media print`、`web/assets/app.css`）**で、アプリ枠（タブバー/サイドバー/設定/エディタ）を隠し配色を印刷向けに上書きする方式。mermaid もライトで印刷するため、印刷用コードテーマ `#print-code-theme`（`@media print`）を併用する。Light 系スタイルではほぼ見た目が変わらない。
- **上書きしている配色**は 2 段構え。
  - **全スタイル共通**（`app.css` の `@media print`）: 本文の背景（白）と文字色（黒）、見出しの文字色（黒）、コードの背景。
  - **ダーク系（`colorScheme: dark`）のスタイルだけ**（2026-09-25 追加）: 引用（文字色・背景・左ボーダー）、表（境界線・ヘッダ背景・行背景）、リンク、区切り線、リストのマーカー、見出しの色・下線色、コードの背景を、**ライトのプリセットの配色に差し替える**。Go の `style.PrintVars` が差し替える CSS 変数を返し、`#styleblock` に `@media print{ #content{ … } }` として出力する（明るいスタイルでは空で、何も出さない）。組版（フォント・サイズ・余白・見出し下線の有無）は差し替えない。それまでは上記の共通分しか変換しておらず、ダーク系で印刷すると引用や表の見出し行が暗い背景のまま（「背景のグラフィック」有効時）、引用・リンク・リストのマーカー・区切り線が淡色のまま紙に出ていた。
  - **明るいスタイル（ライト／GitHub 風／セピア／ユーザー作成の明るいスタイル）は、引用や表などの配色を画面のまま印刷する**（2026-09-25 判断。セピアの引用背景など、ユーザーが設定した色を印刷でも残すため）。
  - **確認状況**: Windows は実アプリ（正式ビルド `ddf5340-dirty` の `.exe`）で「ダーク (プリセット)」の印刷を確認済み（2026-09-25。本文・見出し・リンク・リストのマーカー・引用・表・区切り線・脚注と遮断画像の控えめな色・コード・mermaid がいずれも紙向けの配色で出る）。明るいスタイル（セピア）が画面の配色のまま出ることは Edge 153（WebView2 と同じエンジン）での印刷で確認。**Linux も実アプリで確認済み**（2026-09-26。正式ビルド `1b8e1b3` のバイナリ。Ubuntu 24.04・WebKitGTK 4.1〔2.52.6〕。GTK 印刷ダイアログの「ファイルに出力する」で PDF 化）: 「ダーク (プリセット)」の印刷は、引用・表・リンク・区切り線・見出しの下線・コードの色が**ライトで印刷した場合と画素単位で一致**し（1 ページ目の主要色の画素数が同数・ダークの配色の色は 0）、脚注は控えめな色で区切り線 1 本。「セピア (プリセット)」は引用・表・区切り線・リンクがセピアの配色のまま出る。mermaid と遮断画像を含む文書では未確認。**macOS は未確認**。

## 6. スタイルの保存・共有（可搬性）

- スタイルは OS 設定ディレクトリの設定ファイルに JSON で保存（保存は終了時の `persistSession`／`writeConfig`、読込は起動時の `LoadConfig`＋`web.State.RestoreStylesJSON`）。
- 標準プリセット **ライト / ダーク / GitHub 風 / セピア** を同梱し、複製して編集できる（builtin は直接編集不可、複製して編集）。表示名は **「ライト (プリセット)」** のように接尾辞を付け、ユーザーが「ライト」等の名前を使えるようにする（`PresetNameSuffix`）。
- **スタイル名は全スタイルで一意**（プリセット含む。前後空白を無視した厳密一致で判定）。
  - **複製**: `「基底名」 のコピー`（プリセットからの複製は接尾辞を除いた基底名を使う）。既に在れば `… のコピー 2`, `3`… と自動で一意化（`UniqueName`）。
  - **改名**: 空・重複は**適用せず**現在名へ戻す（`RenameActiveStyle` が成否を返す）。〔入力欄への**インライン警告表示は未実装**——現状は黙って現在名に戻る〕
  - 内部 ID（`user-…`）はスタイルの安定ハンドルとして別に持ち、表示・重複判定には使わない。
- **エクスポート/インポート**（ファイルベースで別マシン・別 OS へ持ち込み、同梱フォントと相まって同一表示を再現）は**実装済み**。
  - **入口**: ネイティブメニュー「**ファイル → スタイル → インポート... / エクスポート...**」（`menu:style-import` / `menu:style-export`）**のみ**。設定パネル内のインポート/エクスポートボタンは廃止し、パネルは「アクティブを編集する」操作に専念させる。
  - **単位**: 1 スタイル＝1 ファイル（拡張子 `.json`）。
  - **ファイル形式**: メタ情報付きの封筒で包む。

    ```json
    { "app": "Markmiru", "kind": "style", "version": 1, "style": { /* Style */ } }
    ```

  - **エクスポート**（`POST /settings/export`）: **アクティブなスタイル**を対象に、`style.SerializeStyle` で封筒 JSON 化し、Go 側 `ExportStyleDialog`（`Host.ExportStyleDialog`）で保存先を選び `WriteFile` で書き込む。〔複数スタイルから選ぶ専用ピッカーは**未実装**——現状はアクティブスタイルのみを書き出す。〕
  - **インポート**（`POST /settings/import`）: `Host.ImportStyleDialog` で選んだファイルを `style.ParseStyleFile` が検証（`kind` が `style` か）＋ `NormalizeStyle` で欠損補完し、`AddImportedStyle` で取り込む。取り込みは常に**新規 ID・`builtin:false`**で、名前は `UniqueName` により**自動で一意化して追加**（同名があれば `… のコピー 2`, `3`… ではなく一意名で付与）。取り込んだスタイルをアクティブ化する。
    - 〔**上書き / 別名で追加 / キャンセルを選ばせる確認ダイアログは未実装**——現状は常に一意名で新規追加する（既存スタイルは書き換えない）。〕
    - 〔不正なファイルの**エラー通知ダイアログも未実装**——現状は解析失敗を無視し、状態は変更しない。〕
  - **実装**: 直列化/検証・正規化は `style/style.go`（`SerializeStyle` / `ParseStyleFile` / `NormalizeStyle`）、名前の一意化・重複判定は `UniqueName` / `NameTaken`、状態操作は `web/state.go`（`AddImportedStyle` / `RenameActiveStyle` / `RemoveActiveStyle` / `DuplicateActiveStyle`）、エンドポイントは `web/web.go`（`/settings/export` / `/settings/import` / `/settings/rename` / `/settings/delete` / `/settings/duplicate`）。

## 9. 編集モードのエディタ外観（実装）

編集モードは **透明 `<textarea>` に chroma のハイライト層を重ねるオーバーレイ**で実装する（CodeMirror 等の大型 JS エディタは使わない。[`技術選定.md`](技術選定.md) §5.3）。「**閲覧重視・メモ帳的編集**」の方針に沿い**最小限**とする。

- **構造**: `<pre class="chroma hl">`（chroma 出力の色付き表示専用層）の上に、透明文字＋実キャレットの `<textarea class="editor-input" wrap="soft">` を重ねる（`inset:0`・同一フォント/パディング/折り返しで完全一致させる）。入力は `POST /tabs/{id}/content` でデバウンス再ハイライトし、ハイライト層（`#hl-{id}`）を差し替える。スクロールは glue が textarea → ハイライト層へ同期する。
- **閲覧用スタイルとは別**扱い（スタイルへは含めない）。スタイルとの連動は **Light/Dark（`colorScheme`）の追従のみ**。

| 項目 | 実装 |
|------|------|
| 構文ハイライト | **控えめな Markdown 構文ハイライト**（オーバーレイ専用の簡易レキサ `render.editorMarkdownLexer`。見出し `gh`/`gu`・強調 `gs`・斜体 `ge`・引用・行内コード・フェンス行等を控えめに色分け。色はスタイル変数に連動し light/dark 両対応）。**すべてのトークンが 1 行内に閉じる**規則のみで構成し、chroma 標準 markdown レキサの「行内コードが改行をまたいで後続を丸呑みし、途中からハイライトが消える」問題を構造的に排除。フェンスコードの**中身は素のテキスト**（言語別ハイライトへの委譲はしない＝控えめ方針） |
| 配色テーマ | **本文スタイルの Light/Dark に連動**（chroma の github / github-dark） |
| 書体 | **等幅**（`--md-code-font` = Noto Sans Mono ＋ 日本語は Noto Sans JP フォールバック）。サイズは `--md-code-size` |
| 行の折り返し | **ソフトラップ**（`wrap="soft"` ＋ `white-space: pre-wrap`）。既定で有効 |
| 行番号 | **無し**（プレーン textarea のため）。将来拡張 |
| 現在行ハイライト / 空白文字の可視化 | **無し**（textarea では持たない）。将来拡張 |

- 標準的な編集操作（元に戻す／やり直し・切り取り／コピー／貼り付け・すべて選択）は **textarea のネイティブ処理**と、ネイティブメニューからの glue `editExec`（`document.execCommand`）で行う（§アーキテクチャ §5.10）。
- 検索（Ctrl+F）は glue のページ内検索（CSS Custom Highlight API）で、編集モードではハイライト層（`.hl`）を対象に走査する（閲覧モードと共通ルーチン。§アーキテクチャ §5.12）。
- 複数選択／複数カーソル・矩形選択、選択なしコピー等の高機能は**持たない**（textarea は常に単一選択）。折りたたみ・自動補完・lint も無い（最小方針）。
